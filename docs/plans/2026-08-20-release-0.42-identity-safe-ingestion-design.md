# Codemem 0.42: Identity-Safe Ingestion

**Status:** Approved
**Date:** 2026-08-20
**Tracking:** `codemem-lmod`

## Goal

Release the post-0.41 adapter, device-identity, and sync work without allowing a
viewer-backed ingestion client to write raw events into the wrong local database.

The 0.42 scope is frozen at merged `main` through PR #1486 plus the targeted
identity-safe ingestion fix. PR #1473 and the Pi integration stack remain outside
this release.

## Confirmed failure mode

Viewer address selection and database selection are independent. If a viewer is
already listening on the configured port for one database while a client expects
another `CODEMEM_DB`, pack and prompt-ledger requests reject the mismatch, but
raw-event ingestion currently succeeds. Prompt and response content can therefore
be persisted to the wrong local database without an error.

The CLI and direct fallback paths already resolve the intended database correctly.
The missing protection is limited to viewer-backed raw-event ingestion.

## Design

### Request targeting

New OpenCode, Claude, and Codex ingestion clients include two optional top-level
fields in raw-event requests:

- `db_path`: the canonical database path expected by the client;
- `identity_target`: the expected runtime identity contract already used by pack
  and prompt-ledger requests.

The fields remain optional on the server so 0.41 clients continue to work against
a 0.42 viewer.

### Server validation

The canonical raw-event route and the Claude and Codex compatibility routes apply
the same database and identity comparison policy as pack and prompt-ledger routes.
Validation happens after bounded JSON parsing and before any session or event
write.

The server returns structured conflict responses for:

- viewer database mismatch;
- viewer identity mismatch;
- unsupported identity contract.

Equivalent database paths are accepted. Requests omitting both targeting fields
retain the 0.41 behavior.

### Client fallback

New clients treat a targeting conflict as a terminal viewer mismatch and invoke
the existing identity-correct CLI or direct fallback exactly once. They do not
retry the mismatched viewer and do not drop the event.

### Explicitly deferred

- authenticating the client-asserted event `source`;
- changing viewer startup or port-collision behavior;
- requiring targeting fields from older clients;
- broad pack, ledger, identity, or sync refactors.

## Validation

Automated coverage must prove:

1. mismatched database and identity requests return conflict responses;
2. conflict responses occur before any event or session write;
3. path-equivalent databases succeed;
4. omitted targeting fields remain accepted;
5. OpenCode, Claude, and Codex clients send targeting fields;
6. mismatch responses invoke the intended fallback exactly once.

Release validation additionally covers a local two-profile viewer collision,
packaged plugin smoke, Claude and Codex transport/fallback behavior, device setup,
recipient-bound sync authentication, the standard repository gate, and the build.

## Pull request stack

1. `fix(ingest): bind viewer raw events to database identity`
2. `docs(release): validate 0.42 candidate`
3. `chore(release): prepare 0.42.0`

The third PR prepares the release but does not tag it. Tagging occurs only after
the release PR merges and the merged `main` commit passes tag preflight.
